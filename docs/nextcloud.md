# Shared Nextcloud account

The account belongs to `services/nextcloud.py`. Attention owns CalDAV discovery,
events, recurrence, task completion and editing in `attention/nextcloud.py`.
Files and Music have no Nextcloud functionality yet.

Use `$XDG_CONFIG_HOME/zephyrus-shell/nextcloud.json` (normally
`~/.config/zephyrus-shell/nextcloud.json`). Start from
[`services/nextcloud.example.json`](../services/nextcloud.example.json):

```json
{
  "url": "https://cloud.example.com/",
  "username": "your-username",
  "credentials": {
    "dav": {"provider": "file", "file": "dav-app-password"},
    "music": {"provider": "file", "file": "music-api-key"}
  },
  "capabilities": {
    "dav": {"credential": "dav"},
    "music_subsonic": {"credential": "music"}
  }
}
```

The URL is the HTTPS instance root, including any installation subdirectory.
Credential references resolve beneath `credentials/nextcloud/` in the same
Zephyrus configuration directory. They cannot be absolute paths or traverse out.
Files must be owned by the current user, regular files with exactly `0600`
permissions. Symlinked credential files are refused. Keep both credential
directories at `0700`. Configuration contains references, never passwords.

The DAV app password comes from Nextcloud Personal settings → Security and can
serve CalDAV and future WebDAV consumers. The Music API key comes from the
Nextcloud Music app's Subsonic/Ampache integration settings. It is a separate
credential. `music_subsonic` records that future capability; no Music API client
or key validation is implemented. Omit the Music entries until you need them.

For a new DAV credential, enter it without echoing it or putting it in history:

```sh
nc_directory="${XDG_CONFIG_HOME:-$HOME/.config}/zephyrus-shell/credentials/nextcloud"
install -d -m 700 "$(dirname "$nc_directory")" "$nc_directory"
(umask 077
 read -rsp 'Nextcloud app password: ' nc_secret
 printf '%s' "$nc_secret" > "$nc_directory/dav-app-password"
 unset nc_secret)
chmod 600 "$nc_directory/dav-app-password"
unset nc_directory
```

`FileCredentials.read(reference)` is the narrow provider interface. A later
Secret Service provider can replace it at the shared service boundary without
rewriting calendar consumers. No keyring dependency is required today.
The shared DAV transport restricts authenticated requests and redirects to the
same HTTPS account and consumer scope, and reports errors without server bodies
or credential values.

## Migrate existing configuration

```sh
python3 scripts/migrate-nextcloud.py
```

This explicitly moves account ownership out of `attention.json`, preserves its
weather and calendar/task selections in `calendar`, and puts the two legacy files
(`nextcloud-app-password`, `nextcloud-music-password`) in the private directory.
A configured legacy `password_file` is honored. The old Music filename is treated
as an API key; verify that it contains the key generated by Music, since migration
does not test it against the server.

Migration refuses mismatched accounts, conflicting destination contents, empty
credentials and symlinks. It writes credentials and canonical configuration
before removing originals, can resume after interruption, and leaves
`attention.before-nextcloud.json` as a configuration backup. It never prints
credential contents. Missing passwords remain missing and the panel prompts you
to supply one. The repository ignores credential directories and the legacy
filenames; keep your real XDG configuration outside the checkout.

Calendar selections remain feature configuration in `attention.json`:

```json
"calendar": {"calendars": ["Personal"], "task_lists": ["Tasks"]}
```

Omit either selection to include all discovered collections; an empty array
selects none. Runtime account loading uses only `nextcloud.json`. Legacy selection
keys are temporarily accepted, but legacy account/password ownership requires
the explicit migration above.

Focused verification: `python3 -m unittest discover -s tests -p test_nextcloud.py -v`.
Existing Attention tests continue to cover calendar and task behavior.
